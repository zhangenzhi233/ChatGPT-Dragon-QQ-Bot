# QQ 晚间回复与动态修复

修复记录：2026-10-10；随 2026-10-15 源码更新一并纳入。

## 最终行为

- 普通长回答按自然句段拆成约 120～240 字符的多条消息，短尾段、代码块及完整代码行允许例外。取消长度/段数超限后替换“不晓得/不知道”和强制合并三条的分支；保留括号、中文代码参数、换行和缩进。长文、代码不注入随机错别字，短文本仍尊重既有选项。显式关闭分段、语音跳过后处理保持有效。
- 保留原来的串行发送：全部文本按顺序发送后才结束私聊轮次，表情/图片只附在最后一条。未知发送结果不重放已发送部分。
- Planner 网络/5xx/硬超时在工具执行前最多恢复两次，退避 5/15 秒；新消息优先，停止/取消立即生效，401/403/429 不重试。单轮异常不会再杀死后台消费者。此修复提高故障恢复能力，上游网络错误具体来源仍未查明。
- 空间配图使用正文短标签与当前角色名查询。候选必须可解码且通过图像校验；无对应情绪时使用角色库已有的“问候”标签，仍无图则明确失败，不混用其他角色，也不增加权限。
- 自动动态拆分为准备、发布两个阶段。准备失败可在 18～22 点内间隔 15 分钟最多重试两次，次数跨重启保存；在首次调用发布接口前持久记账，发布失败或回执不明当天不重发。旧 attempted 状态保留；状态损坏或写入失败拒绝自动发布。手动额外发送仍使用原有入口。

## 实际验证

- 191 项相关 pytest 通过，包含长句、未闭合代码围栏、跨消息缩进、消费者异常继续工作、重试上限/取消、新消息抢占、配图身份/损坏校验、发布前记账和模糊回执不重发；现有语音回归通过。
- 相关核心文件 Ruff 通过；7 个部署源码文件在实际 Python 环境中完成语法检查。
- 三份故障原回答在维护副本及部署后实际代码/依赖中离线回放：两份编程解答各 5 条、睡前故事 2 条，正文逐字符重构一致；模拟发送确认附件一次且在最后，全部发送后才 stop。测试未请求模型、未发 QQ 或动态。
- 本机 QQ 在线/账号匹配、四插件 loaded/success，WebUI 正常，NapCat 恰好一个机器人 WS 客户端。模型桥接连接正常；8 份关键配置及原有 QQ 进程不变。
- 2026-10-10 扩展运行主动聊天插件原有测试时，有 6 项受真实午夜静默时段影响失败，不属于当时以上 191 项通过集合。2026-10-15 已另行更新主动聊天并完成包含该插件的 210 项相关回归；结果仍不能代表全仓测试通过。
